# Timelog C Core Foundation Audit

## Executive Summary

I read `CLAUDE.md` and every file under `core/src/internal/` and `core/src/storage/`. The code is not generally “random wheel reinvention.” The hot machinery is mostly project-specific: immutable in-memory pages/segments/manifests, L1 non-overlap, half-open ranges, tombstone max-seq filtering, custom allocation, and free-threading-safe publication. Those constraints are explicit in [CLAUDE.md:7](/home/vldvhk/Documents/timelog/CLAUDE.md:7), [CLAUDE.md:104](/home/vldvhk/Documents/timelog/CLAUDE.md:104), [CLAUDE.md:120](/home/vldvhk/Documents/timelog/CLAUDE.md:120), [CLAUDE.md:127](/home/vldvhk/Documents/timelog/CLAUDE.md:127), [CLAUDE.md:187](/home/vldvhk/Documents/timelog/CLAUDE.md:187), and [CLAUDE.md:279](/home/vldvhk/Documents/timelog/CLAUDE.md:279).

The real simplification targets are narrower: speculative V2 page-delete plumbing, repeated vector/reserve boilerplate, duplicated binary-search kernels, and dead/test-only internal APIs. I would not vendor klib/stb/uthash/CK/liburcu into the hot core unless a benchmark proves parity; most candidates either do not fit `tl_alloc_ctx_t`, add callback/global-allocation shape, or fail the MSVC/TSan/free-threaded constraints.

## Prior-Art Rejections

Concurrency Kit and liburcu are the wrong replacement for the current sync/refcount/seqlock layer. The code deliberately uses C11 atomics on GCC/Clang, MSVC Interlocked intrinsics on MSVC, `_beginthreadex` on Windows, pthread condvars with monotonic-clock handling on POSIX, and acq_rel refcount release to stay TSan-clean: [tl_atomic.h:17](/home/vldvhk/Documents/timelog/core/src/internal/tl_atomic.h:17), [tl_sync.c:147](/home/vldvhk/Documents/timelog/core/src/internal/tl_sync.c:147), [tl_sync.c:294](/home/vldvhk/Documents/timelog/core/src/internal/tl_sync.c:294), [tl_refcount.h:7](/home/vldvhk/Documents/timelog/core/src/internal/tl_refcount.h:7), [tl_seqlock.h:15](/home/vldvhk/Documents/timelog/core/src/internal/tl_seqlock.h:15). CK is permissively licensed but brings architecture/platform assumptions and mixed file licenses; liburcu is not a good vendored wheel dependency fit.

klib/stb_ds/uthash are legitimate prior art for small vectors/hash/list utilities, but they are not an obvious win here because the hot structures need `tl_alloc_ctx_t`, `tl_status_t`, exact layout, and no callback/global allocator penalty. License source checks: klib MIT, stb MIT/public-domain, uthash BSD-style, Concurrency Kit BSD-style with noted additional licensed pieces, Unity MIT: https://github.com/attractivechaos/klib/blob/master/LICENSE.txt, https://github.com/nothings/stb/blob/master/LICENSE, https://raw.githubusercontent.com/troydhanson/uthash/master/LICENSE, https://raw.githubusercontent.com/concurrencykit/ck/master/LICENSE, https://github.com/ThrowTheSwitch/Unity/blob/master/LICENSE.txt.

## Ranked Shortlist

1. Remove V2 page-delete plumbing or hide it behind an explicit `TIMELOG_EXPERIMENTAL_ROW_DELETE` build flag.
2. Add a local allocator-aware reserve/pointer-vector helper; do not vendor kvec/stb_ds.
3. Deduplicate lower/upper-bound code with macro/static-inline specializations and benchmark before/after.
4. Prune dead/test-only internal APIs after deciding whether internal tests are allowed to test private conveniences.
5. Factor segment prefix-count construction and manifest pointer-list boilerplate.
